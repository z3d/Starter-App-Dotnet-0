# 2026-09-08 — Consistency suite assessment and simplification audit

Two passes in one session: a repo-wide over-engineering audit (ponytail), re-weighed for a
template, and a check of whether the advisory consistency suite still does what its design
post describes. Design rationale for the suite: <https://z3d.github.io/blog/consistency-checks/>.

## Consistency suite — is it working?

**Mechanically, yes.** `ConsistencyScorer` matches the post: features z-scored against the
cohort, exemplar covariance regularised with Ledoit-Wolf shrinkage, Mahalanobis distance from
the exemplar centroid. Governance tests prove the centroid anchors on the pinned exemplars, not
the full cohort. Reports regenerate into `docs/_local/consistency-*.txt` on every run of the
fast filter. The one finding it produces is real: `CreateOrderCommandHandler` is the sole
two-sigma outlier, and the divergence layer states why (about three times the exemplar IL, four
private methods against an expected zero or one, three entity loads against one).

**Three drifts from the post's intent, fixed the same day (resolution below):**

1. **Exemplar READMEs describe two deleted layers.** Commit `968455e` removed the AST-shingle and
   token-"embedding" layers as stubs. `docs/exemplars/*/README.md` still open with "reports all
   three measurement layers" and table both. The governance test parses those files, so they look
   maintained.
2. **Two tests gate the build on a distance.** `StructuralFingerprint_KnownOutlierExceedsOneSigma`
   fails unless `CreateOrderCommandHandler` sits above mean plus one sigma;
   `StructuralFingerprint_CapturesCreateOrderComplexity` fails unless it has at least three
   private methods and IL above 1.5x the median. The post's rule is that distance "punishes the
   first good example of a new pattern" and the testing-strategy skill says builds never gate on
   a distance. Simplifying that handler breaks the build for being more consistent. The
   `ConsistencyIsAdvisoryTests` meta-scanner that guarded this was deleted in the same commit.
   Fix: convert both to synthetic-fixture tests (the extraction tests added in `968455e` already
   cover the vacuous-zeros risk) or delete them.
3. **No review step reads the report.** Nothing in `.claude/agents/`, the architect-review
   workflow, or the architecture-review skill opens `docs/_local/consistency-*.txt`. Fix: one
   line in the backend-architect agent or the workflow prompt.

**Signal at template scale.** The post's reference cohorts had 20-34 members; here 9, 7 and 5
with 3-4 exemplars each. The query cohort reports no divergence on any feature and distances
within a 0.6 band. The EF cohort's two "divergent" configurations are divergent because small
entities have fewer properties. Expected for a template; improves as a derived project's cohorts
grow. Not a defect, but the current output is one useful line in three files.

### Resolution — 2026-09-08

All three fixed in the same change. READMEs now describe the two surviving layers. The two
`CreateOrderCommandHandler` gates are deleted; `ConsistencyScorerTests.ScoreAll_OutlierRanksHigherThanSimilar`
already proves ranking on synthetic data and the `968455e` extraction tests cover the
vacuous-zeros risk, so no coverage is lost. The backend-architect agent now reads
`docs/_local/consistency-*.txt` when present, as a prompt to look and never as a finding by itself.

  A swap is a redesign, not a cut.
- **Length guards → `ThrowIfGreaterThan`.** Domain tests pin the exact exception type and message,
  and the validator-guard sync rule references the messages.
- **Second look, 2026-09-09.** Three of the declines did not survive re-checking. The replayer's
  "a test keeps the constants in sync" reason was a misread: `OutboxReplayTests` compares the SQL
  to `OutboxMessage.ResetForReplay`, not one constant to the other, so `ReplayByIdSql` is now
  derived from `ReplayAllErroredSql` plus one line. Nothing snapshots the OpenAPI output, so the

## Process note

`PerfSeedScriptTests.PerfSeedScript_SeedsBulkOwnerScopedData_AndIsIdempotent` failed in three of
six full-suite runs today and passed alone every time. Root cause: the DbUp execution timeout in
both seed tests was two minutes, a hang guard sized like a performance budget. The perf seed runs
three 20,000-row `generate_series` inserts twice (the idempotency pass), about a minute per pass
alone, and under the parallel Integration collection one pass crossed two minutes and surfaced as
an Npgsql "Timeout during reading attempt". Fixed in this record's branch by raising the guard to
ten minutes in `PerfSeedScriptTests` and `DastSeedScriptTests`. The mirror-generation commit
earlier today bypassed the pre-commit gate on this flake after format, build and the fast filter
were green.
