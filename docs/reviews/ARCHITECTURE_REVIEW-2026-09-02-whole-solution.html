Assessment

Every load-bearing control was re-derived from code rather than trusted: JWT validation parameters, the single ICurrentUser writer, owner scoping in every SQL predicate and every mutation handler, owner-hashed cache keys, one SaveChangesAsync per handler with the order id minted outside the retry delegate, outbox claim and salvage under SKIP LOCKED, the Service Bus topology bijection, and the exception-to-status table. None has regressed since 4 August, and the nine findings recorded then are all still open.

The two findings that matter operationally are the loss of every security header and the correlation-id echo on exception-mapped responses, and a health check that builds a fresh Azure credential per probe on two unthrottled, unauthenticated routes. Three candidates that looked like high-value convention gaps were dismissed because an analyzer, an existing test, or a recorded decision already closes them.

MediumFixed · 47d20e7

Exception-mapped responses lose every security header and the correlation-id echo

src/StarterApp.Api/Program.cs:61-66 · Infrastructure/WebApplicationExtensions.cs:7-22 · Infrastructure/Payloads/PayloadCaptureMiddleware.cs:57

Payload capture sets X-Correlation-ID before calling next, and the security-headers middleware appends CSP, frame options and referrer policy before calling next. The exception handler sits between them and calls Response.Clear() before writing ProblemDetails, wiping every header set so far without re-running downstream middleware. HSTS is eager too. Every validation 400, 404, 409, 503 and 500 therefore ships with no security headers and no correlation id, which breaks the documented support workflow on exactly the responses support gets asked about. CORS survives only because it uses OnStarting. No test asserts a header on an error response.

Fix appliedRegister both header sets via Response.OnStarting. Reordering the middleware does not help. Add one integration test that triggers a 409 and asserts the correlation id and security headers.

MediumFixed · 47d20e7

The payload-archive health check builds a blob client and Azure credential per probe

Infrastructure/HealthChecks/PayloadArchiveHealthCheck.cs:17-26 · Infrastructure/ServiceCollectionExtensions.cs:217 · Program.cs:87

The check constructs its client in the constructor and is registered only through AddCheck<T>, so the health service activates a fresh instance every run. In managed-identity mode each probe creates a DefaultAzureCredential with an empty per-instance cache and performs a full chain walk plus an IMDS token fetch. It is reachable from the unpredicated /health, which runs every registered check and is hammered by the k6 smoke, and from /healthiness. Both are unauthenticated and rate-limit-exempt. IMDS throttling would flip both probes to 503 on a healthy storage account. The three sibling checks inject their clients and a warm singleton already exists.

Fix appliedExpose the singleton BlobServiceClient in DI and inject it, collapsing the duplicated connection-string resolution. Consider a predicate on /health.

MediumFixed · 47d20e7

Route-path entity references bypass the sensitive-name filter

src/StarterApp.ServiceDefaults/Payloads/PayloadEntityReferenceExtractor.cs:57,178-194,274-286

The extractor's own comment and the decisions log say a sensitive *Id such as nationalId never becomes a blob path segment. The metadata and JSON-body branches honour that through IsSensitivePropertyName; the route branch never receives the token list and AddReference does no screening. Capture runs before routing and authentication and records 404 traffic by design, so an unauthenticated GET /api/v1/nationalId/123-45-6789 lands the value in an entity-index blob name and an Information-level log line the Serilog masking stack does not touch. Today no template route carries PII in its path, so the leaked value is caller-supplied; the exposure is a broken documented invariant that a derived project inherits silently. A sibling worktree has staged a value-level screen, which does not cover the name-level case.

Fix appliedThread sensitiveTokens into AddRouteReference and screen caller-supplied EntityReferences the same way. Extend the existing sensitive-name test with a route-derived case.

MediumFixed · 47d20e7

Four hand-rolled raw IL byte loops remain, two behind negative assertions

Tests/Conventions/DomainConventionTests.cs:303 · CachingConventionTests.cs:216 · AppHost.Tests/PayloadCaptureConventionTests.cs:51 · ProductionAssemblyConventionTests.cs:81

The testing skill says never to hand-roll a raw IL byte loop, and IlInstructionWalker exists for that reason. These four scan bytes for 0x28 or 0x6F and only advance past operands after a call-looking byte, so every other opcode's operand bytes are read as opcodes. The verifier corrected the finder: garbage tokens throw inside a swallowed catch, so the hazard is not a false positive but a skipped genuine call. That is a silent pass for the two negative checks (no RaiseDomainEvent from constructors, no DateTime.UtcNow in production code) and for the cohort filter that decides which handlers the cache-invalidation rule covers. No meta convention forbids the pattern.

Fix appliedRewrite the two Tests sites over IlInstructionWalker.Walk. Link the walker file into AppHost.Tests and rewrite the other two. Add a housekeeping convention that fails on the raw opcode literals outside the walker.

The emulator reset script cannot run on macOS and performs half the documented recovery

scripts/reset-servicebus-emulator.sh:18,27 · .claude/skills/development-workflow/reference/service-bus-emulator.md:85-90

mapfile is a bash 4 builtin. The documented Apple Silicon dev target ships bash 3.2.57 as /bin/bash, so the script exits 127 under set -e before touching a container. It also removes only the two containers while the skill calls the stale Aspire network the most common reason a clean retry fails, then prints that state is cleared. Nothing references the script. It is the only bash 4 construct in the repo and there is no shell lint in CI.

Fix appliedReplace mapfile with a while read loop over an initialised array, add the network removal, link the script from the skill's recovery section, and filter on Aspire's DCP label rather than a name prefix.

×
Noise

Endpoints bind a CancellationToken but nothing checks it is forwarded

AnalysisMode=All applies the SDK's global config, which promotes CA2016 to a warning, and warnings are errors here. Every endpoint handler is a named method group, so the analyzer's lambda blind spot does not apply. The convention test covers the declaring half; the compiler covers the forwarding half.

×
Noise

Exported-only cohort discovery lets an internal handler escape the owner-policy conventions

The every-command-has-a-handler test enumerates commands with all types and handlers with exported types only, so an internal handler fails the build as a missing implementation. Coverage is transitive rather than intrinsic; switching the helper is an optional one-line hardening.

×
Recorded decision

Unauthenticated traffic bypasses the rate limiter because it runs after authorization

Mechanically true and deliberate. The decisions log delegates inbound volume to the upstream gateway and scopes the in-app limiter to fairness between verified identities. Changing it is a new decision, not a bug.
