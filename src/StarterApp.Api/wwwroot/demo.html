01 / PROBE

Check the rig is healthy

GET /healthiness runs real round-trips against the durable resources: Postgres, the cache, a Service Bus AMQP link, the payload archive — every check tagged durable. No token required — probes are anonymous by design.

02 / IDENTITY

    
Sign in — mint a real token

    
In a deployed environment your IdP issues the token. Here the local Keycloak realm does: a password grant for the dev user returns an RS256-signed JWT with audience starterapp-api. The API validates issuer, audience, signature, and expiry itself — zero trust, no perimeter assumptions. The scopes you tick below are requested on the token; untick orders:write later, sign in again, and the order step will refuse you with a 403.

05 / ORDER

    
Place an order — the async pipeline

    
POST /api/v1/orders reserves stock and writes the order row and an OrderCreated event into the outbox in one commit, then returns 201. A background processor publishes the event to Service Bus; the Functions consumers (order-confirmation email, inventory reservation) pick it up off their topic subscriptions. Then drive the order forward: PUT /api/v1/orders/{id}/status raises an OrderStatusChanged event the same way.

06 / END

    
That's the pipeline

    
IdP-issued tokens in, verified by the API itself (issuer, audience, signature, expiry); synchronous writes for catalog and customers; a transactional outbox that publishes order events to Service Bus topics; idempotent Functions consumers off those subscriptions. Payloads captured throughout. Keep going in Scalar (same origin — try-it just works) or the Aspire dashboard for traces.
